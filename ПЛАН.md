# План: сайт подготовки к коллоквиуму

Рабочая папка сейчас содержит только PDF учебника (208 страниц, текстовый слой снят ABBYY FineReader). Исходный проект — `Desktop\jp`. Код пока не копировался: этот файл фиксирует план до начала реализации.

## Что переносится

Оболочка `jp`: Vite, React 19, свой роутер на `history` (не React Router), страницы из `PAGE_META`, стили, карточка по колёсику, тренажёр чисел, локальное состояние. Копировать дерево без `node_modules`, `dist`, `.git`, кэшей и `test-results`, затем новый `git init` и `npm install`. Японские данные и механики остаются в репозитории с пометкой `неактуально`.

Главная сущность — **положение**. Это общий тип для определения, аксиомы, принципа, леммы, теоремы, следствия, критерия, свойства, замечания и примера. Вид хранится в поле `kind`, на экране пишется «Теорема», «Определение» и так далее.

Соответствие сущностям japanese:

| В japanese | В этом сайте |
|---|---|
| Кандзи, его страница и пометка «выучено» | Положение, страница `/p/:id`, пометка «выучено» |
| Колёсико / долгое нажатие → `KanjiInfoCard` со стеком | То же: быстрый просмотр без ухода со страницы |
| Слова, в которых встречается кандзи (`words-by-kanji`) | Положения, в тексте которых есть ссылка на текущее |
| Состав кандзи и «входит в» | Отдельный граф развития: из чего следует что |
| `KanjiChip` внутри текста | Кликабельная фраза или формула в формулировке и доказательстве |
| Тренажёр чисел: пул, адаптивный/равномерный выбор, сессия | Тренажёр вопросов и положений |
| Теория как список уроков | Главная: раскрывающийся список из 23 вопросов |
| Аккаунт, кана, частицы, глаголы, словарь, читалка, аналитика, озвучка | Код остаётся, из навигации и главной убран |

Ссылки в тексте и граф развития — разные связи. Упоминание в доказательстве («этот переход по теореме 2.1») — это ссылка. Ребро графа — явный список `dependsOn`: что нужно раньше, чтобы получить текущее положение. Обратные списки считаются из данных, в JSON не дублируются.

## Данные

Одно положение — один объект:

- `id`, `kind`, номер из учебника (`1.6`, `2.1`), заголовок
- формулировка, доказательство и замечания как блоки
- блок состоит из кусков: текст, формула LaTeX, ссылка `{ statementId, видимая фраза, необязательный комментарий }`, рисунок `{ src, подпись }`
- `dependsOn: string[]`
- источник: страница PDF

Вопрос коллоквиума: номер, текст, упорядоченный список `id` положений, пометки потоков («только для…» / «кроме…»). Пока поток не выбран, показываются все вопросы, пометка потока остаётся у пункта. Фраза про пункты 1–6 программы в данных предусмотрена, текста программы в материалах нет — раздел заполнится, когда программа появится.

Рендер формул — KaTeX. Рисунков-растров в PDF почти нет (4 картинки), но в тексте есть «рис. 1.1», «рис. 1.4»: слот рисунка нужен сразу, картинка вырезается из страницы, когда до неё дойдёт разметка.

Объём первой очереди — вопросы 1–23, это начало пособия (действительные числа, последовательности, предел функции, непрерывность). Интегралы и дальше — следующие партии. Формулировки переносятся по учебнику, без пересказа. Сомнительный фрагмент помечается в поле `review`, а не затирается догадкой.

## Порядок для агента с субагентами

Субагенты не коммитят. Коммиты делает родитель, по одной законченной правке, с сообщением, зачем она. Общие файлы (`types` роутера, `App.tsx`) правит только родитель. Субагенты пишут в свои каталоги.

**Шаг 0. Родитель.** Скопировать `jp`, инициализировать git, первый коммит — импорт. Завести `src/data/math/` со схемой, пустым банком и 23 вопросами. Расширить роутер: статические страницы как сейчас, плюс `/p/:id` и `/graph`. Включить обход аккаунта и запись состояния только в `localStorage`. Договориться о метке: комментарий `неактуально:` над неиспользуемым модулем, пункт навигации с `navGroup: 'none'`.

**Шаг 1. Параллельно, разные каталоги.**

1. **Оболочка.** Заголовок и главная под коллоквиум. В навигации оставить «Главная», «Тренировка», «Граф». Остальные разделы скрыть, код не удалять.
2. **Страница положения.** Из `KanjiPage`, `KanjiInfoCard`, `KanjiChip`: полный экран, быстрый просмотр по колёсику и долгому нажатию, стек «назад» внутри карточки, клик по ссылке в тексте, блок «используется в», блок «следует из / из этого следует», переключатель «выучено».
3. **Главная.** Раскрывающийся список вопросов. Внутри — ссылки на положения и та же пометка «выучено». У вопроса виден прогресс, например 4/7.
4. **Тренажёр.** Каркас сессии чисел. Два пула: вопрос или положение. Фильтр: выученные или все. Режим: адаптивный или равномерный. На карточке заголовок, по действию открывается формулировка (у вопроса — список положений). Оценка вручную: знаю / не знаю. Верный ответ сам пометку «выучено» не ставит.
5. **Граф.** Страница всех рёбер `dependsOn` и окрестность на странице положения. Пока данных мало, граф может быть списком связей; картинка — когда рёбер станет достаточно.

После шага 1 родитель собирает вертикальный срез на 2–3 положениях со взаимными ссылками и проверяет в браузере: аккордеон, переход, колёсико, «выучено», одна карточка тренажёра.

**Шаг 2. Разметка учебника, тоже параллельно, но после реестра.** Родитель снимает ориентир по страницам и составляет реестр: каждое «Определение», «Теорема», «Лемма», «Следствие» получает `id` и страницу. Дальше субагенты заполняют тела в разных файлах, не заходя в чужие:

- вопросы 1–3, действительные числа и грани
- вопросы 4–9, последовательности до Кантора
- вопросы 10–14, частичные пределы и Коши
- вопросы 15–23, прямая, предел функции, непрерывность

Ссылка может указывать на `id` из реестра, даже если тело ещё пустое. Родитель прогоняет проверку: каждая ссылка и каждый пункт вопроса существуют, `dependsOn` без циклов. Потом коммит на каждый такой кусок.

Если в главе попадётся рисунок, таблица или выкладка, которую схема не вмещает, субагент останавливает эту главу и пишет, какого блока не хватает. Схему меняет родитель одним коммитом, затем разметка продолжается.

**Шаг 3. Родитель.** Скрытые разделы ещё раз сверить с навигацией, прогнать сборку и открыть главную, страницу положения, быстрый просмотр и тренировку.

## Как читать PDF

Повторно прикреплять учебник в чат не нужно: файл уже лежит в папке. Вложение в промпт не открывает страницу «как в читалке». Точный просмотр — это отрисовка нужной страницы в картинку и чтение картинки. Так видны формулы, индексы и рисунки, которые в текстовом слое FineReader развалены.

Текстовый слой годится как дешёвый указатель: найти страницу, заголовок и грубые границы теоремы. Формулировку, доказательство и формулы сверять по картинке страницы.

Оценка расхода, порядок величины: одна страница учебника картинкой — около 1–3 тысяч токенов. Кусок под вопросы 1–23 — порядка 100 страниц, то есть примерно 100–300 тысяч токенов входа, если смотреть каждую страницу один раз. Вся книга, 208 страниц, — примерно вдвое больше. Сюда не входит текст положений, который модель ещё напишет. В длинном чате история пересылается снова, поэтому фактический расход выше суммы страниц. Пачку страниц лучше отдавать отдельному субагенту со своим коротким контекстом.

Смотреть глазами имеет смысл формулировки, определения и страницы с формулами и рисунками. Сплошной просмотр всех 208 страниц до реестра не нужен.
