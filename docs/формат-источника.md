# Схема пакета учебника

Задание на подготовку данных одного учебника для коллоквиума по курсу «Введение в математический анализ». Сдаётся набор JSON-файлов и, если есть, фотографии страниц. Тексты берутся из книги этого автора. Чужой учебник не копируется, недостающие теоремы не дописываются.

Код пакета `<id>` — латиница в нижнем регистре, цифры и дефис, например `zorich-1`. Коды `f1-lectures` и `gusev-2026` заняты. После сдачи `<id>` и `id` положений не меняются.

## Что сдать

Каталог `sources/<id>/`:

| Файл | Содержимое |
|---|---|
| `manifest.json` | Код, подпись в списке учебников, каталог фото |
| `statements.json` | Все положения в порядке чтения книги |
| `depends.json` | Прямые опоры доказательств |
| `formulations.json` | Формулировка для ответа на билете, без доказательства |
| `latex.json` | Формулировка и доказательство с формулами |
| `short-names.json` | Короткое имя карточки |
| `questions.json` | 23 вопроса коллоквиума и пункты из этой книги |
| `report.md` | Отчёт по списку в конце этого файла |

Фотографии страниц, если они есть: `public/sources/<id>/pNNN.jpg`.

Кодировка всех текстовых файлов — UTF-8 без BOM. JSON без комментариев и без висячих запятых. В строках настоящие буквы, а не последовательности `\uXXXX`. Отступ — два пробела.

Пустая строка и строка из одних пробелов запрещены везде, где ниже требуется текст. Такой ключ в объект не кладётся.

## manifest.json

Объект из четырёх полей, других полей нет.

```json
{
  "id": "zorich-1",
  "title": "Зорич В.А.",
  "author": "Зорич В.А.",
  "pagesDir": "/sources/zorich-1"
}
```

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | Совпадает с именем каталога `sources/<id>`. Шаблон: `^[a-z][a-z0-9-]*$`. |
| `title` | строка | Подпись учебника в списке. Формат `Фамилия И.О.`, например `Зорич В.А.`. Без названия книги, без слов «старый» и «новый». |
| `author` | строка | Та же строка, что `title`. |
| `pagesDir` | строка | `/sources/<id>`. Без слэша на конце. |

## statements.json

Непустой массив объектов. Порядок элементов — порядок чтения учебника, сверху вниз. Один объект — одно положение: определение, аксиома, принцип, теорема, лемма, следствие, замечание, пример, задача или вводный абзац параграфа.

Лишних полей нет. Все десять полей ниже обязательны.

```json
{
  "id": "thm-2.9",
  "kind": "theorem",
  "number": "2.9",
  "title": "Больцано — Вейерштрасс",
  "sectionId": "2.5",
  "sectionTitle": "Подпоследовательности и частичные пределы",
  "bookPage": 40,
  "bookPages": [40, 41],
  "text": "Всякая ограниченная последовательность имеет сходящуюся подпоследовательность.\n\nДоказательство.\nТекст доказательства обычными словами.",
  "mentions": [],
  "dependsOn": []
}
```

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | Уникален внутри пакета. Шаблон: `^[a-z][a-z0-9.-]*$`. Без пробелов, без кириллицы. Один и тот же код в разных учебниках допустим: пакеты не смешиваются. |
| `kind` | строка | Ровно одно значение из таблицы видов. |
| `number` | строка или `null` | Номер в этой книге. JSON-число запрещено: `2.10` нельзя записать числом, иначе оно станет `2.1`. Штрих пишется символом `′` или `'`, например `"4.3′"`. У вводного текста параграфа — `null`. Это не номер вопроса коллоквиума. |
| `title` | строка | Короткий заголовок положения, без пересказа формулировки. |
| `sectionId` | строка | Код параграфа. Один и тот же у всех положений этого параграфа. Пример: `"2.5"`, `"4"`. |
| `sectionTitle` | строка | Название параграфа, одинаковое у всех положений с этим `sectionId`. |
| `bookPage` | целое число | Страница, с которой положение начинается. Неотрицательное, без дробной части. Это номер в имени файла фото, а не «печатный номер плюс сдвиг». |
| `bookPages` | массив целых | Все страницы, которые занимает положение, по возрастанию, без повторов. `bookPage` входит в массив. Если положение на одной странице, массив из одного числа. |
| `text` | строка | Полный текст без команд TeX: формулировка, затем доказательство, если оно есть. Формулы — словами или обычными символами. Одиночный перевод строки равен пробелу. Пустая строка разделяет абзацы. |
| `mentions` | массив строк | Коды других положений этого пакета, на которые есть отсылка, но которые не являются опорой доказательства. Нет отсылок — `[]`. |
| `dependsOn` | массив | Всегда `[]`. Опоры доказательств пишутся только в `depends.json`. |

`id` рекомендуется собирать так: префикс вида, дефис, номер параграфа, дефис, номер положения. Префиксы: `def`, `thm`, `lem`, `cor`, `ax`, `prin`, `rem`, `ex`, `task`, `prose`. Штрих в номере передаётся буквой `p` на конце: лемма 3.1′ получает код `lem-3.1p`. Префикс не заменяет поле `kind`.

### Виды

Строка `kind` пишется точно так:

| `kind` | Что класть |
|---|---|
| `definition` | Определение |
| `axiom` | Аксиома |
| `principle` | Принцип |
| `theorem` | Теорема, в том числе утверждение, которое книга называет теоремой или критерием |
| `lemma` | Лемма |
| `corollary` | Следствие |
| `remark` | Замечание |
| `example` | Пример |
| `exercise` | Задача. В вопросы коллоквиума не входит |
| `prose` | Заголовок или вводный абзац параграфа без собственного номера. `number` равен `null` |

В пакет входят все определения, аксиомы, принципы, теоремы, леммы, следствия и замечания из тех глав, по которым составлены 23 вопроса. Примеры входят, если они в книге стоят при таком положении. Задачи можно включить, но для вопросов они не нужны. Вводные абзацы параграфов включаются, если без них теряется обозначение, которым дальше пользуется определение.

Не включать материал после границы, указанной в задании на конкретную книгу. Если граница не названа, граница — конец последней главы, которая нужна для вопроса 23.

### Примеры и задачи

Пример стоит в массиве сразу после положения, которое он иллюстрирует, и имеет тот же `sectionId`. Несколько примеров подряд остаются сразу после этого положения, в порядке книги.

Задача стоит там, где она стоит в книге. В `questions.json` задачи нет.

### Текст

Формулировка и доказательство в `text` разделены пустой строкой. Доказательство начинается абзацем, первые символы которого — слово `Доказательство` и сразу точка:

```text
Всякая ограниченная последовательность имеет сходящуюся подпоследовательность.

Доказательство.
Пусть последовательность ограничена. Дальше текст книги.
```

Так не считается доказательством:

- `Доказательство` без точки;
- `Доказательство отсутствия корня...` внутри формулировки;
- слово «доказательство» в середине предложения.

Если у положения в книге доказательства нет, абзаца `Доказательство.` нет.

Конец доказательства в книге (`□`, `■`, «что и требовалось доказать») в текст можно не копировать.

## formulations.json

Объект «код положения → строка». Ключ есть в `statements.json`. Значение — формулировка, которую произносят на билете: условие и утверждение, без доказательства и без слов «теорема», «лемма», «определение» в начале, если они только называют вид.

Одна формулировка — один или несколько абзацев, как в книге. Формулы здесь можно писать обычными символами (`lim`, `∀`, `ε`) или разметкой из раздела про LaTeX. Длина формулировки положения, которое входит в вопрос, больше 8 символов.

Запись обязательна для каждого `statementId` из `questions.json`. Для остальных определений, аксиом, принципов, теорем, лемм, следствий и замечаний запись тоже нужна. Для `prose` и `exercise` запись не нужна. Для `example` запись нужна только если пример сам стоит пунктом вопроса.

## latex.json

Объект «код положения → строка». Ключ есть в `statements.json`. Значение — тот же текст, что в книге, с формулами. Формулировка и доказательство вместе. Доказательство отделено так же, как в `text`: пустая строка не обязательна, но абзац доказательства начинается ровно с `Доказательство.`.

Запись обязательна для каждого положения из `questions.json` и для каждого положения, в котором есть формула. Если формул нет и текст уже полный, ключ можно не писать.

Разметка формул — только KaTeX:

- строчная формула: `$...$`;
- выключная формула: `$$...$$`;
- скобки `\(...\)` и `\[...\]` не используются;
- внутри `$...$` нет перевода строки и нет второго символа `$`;
- `\emph{текст}` допустим и означает курсив;
- `\tag{...}` допустим только внутри `$$...$$`;
- обратный слэш в JSON пишется дважды: в файле `\\frac`, на странице это `\frac`.

Пример значения после разбора JSON, не как сырой файл:

```text
Если $a_n \to L$, то
$$
\frac{a_1 + \ldots + a_n}{n} \to L.
$$

Доказательство.
Текст доказательства.
```

В сыром JSON этот фрагмент выглядит так:

```json
{
  "cor-2.4-1": "Если $a_n \\to L$, то\n$$\n\\frac{a_1 + \\ldots + a_n}{n} \\to L.\n$$\n\nДоказательство.\nТекст доказательства."
}
```

`text`, формулировка и `latex` говорят одно и то же. `latex` не короче формулировки и не заменяет доказательство пересказом, если доказательство в книге есть.

## short-names.json

Объект «код положения → строка». Ключ есть в `statements.json`. Значение — имя карточки из нескольких слов, не формулировка.

На карточке к имени спереди добавляется вид и номер. Для записи `"thm-2.9": "Больцано — Вейерштрасс"` карточка называется «Теорема 2.9. Больцано — Вейерштрасс». Если записи нет, карточка называется «Теорема 2.9». У примера без записи карточка называется «Пример».

Запись обязательна для каждого положения из `questions.json` и для каждого положения видов `definition`, `axiom`, `principle`, `theorem`, `lemma`, `corollary`, `remark`.

## depends.json

Объект «код положения → массив кодов, из которых доказательство непосредственно следует».

```json
{
  "thm-1.5": ["ax-1-2", "def-1-6"]
}
```

Ребро ставится, когда доказательство использует это положение. Соседство в книге и похожее слово ребром не являются. В массив входят только прямые опоры, без повторов. Положение не ссылается на себя. Каждый код, и ключ и элемент массива, есть в `statements.json`.

Ключ без опор не пишется. Пустой массив и отсутствие ключа означают одно: опор нет.

Номерная фраза в тексте («по теореме 2.9», «по лемме 3.1′») сюда не копируется, если у положения с этим видом и этим `number` запись уже есть. В `depends.json` остаётся опора, которую из номера в тексте не прочитать.

`mentions` — не опоры. Туда кладётся отсылка, которая не нужна доказательству как посылка: «см. теорему 2.6», сравнение, указание на рисунок через положение. Код из `mentions` не повторяется в `depends.json` для того же положения.

## questions.json

Массив ровно из 23 объектов. `number` идёт от 1 до 23 без пропусков и без повторов. `title`, ограничение `streams` у вопроса и сноска вопроса 21 копируются дословно из таблицы ниже. Другой список вопросов не составляется.

Пункты — положения этой книги, из которых состоит ответ. `statementId` есть в `statements.json`. `label` — короткая подпись пункта на русском, по терминологии этой книги. Один и тот же `statementId` может стоять в нескольких вопросах.

Если в книге нет положения для вопроса, вопрос всё равно остаётся в массиве, а `items` равен `[]`. Причина пишется в `report.md`. Пустым может быть отдельный вопрос, не весь файл.

Порядок пунктов — порядок, в котором их используют в ответе. Лемма, на которую доказательство пункта ссылается словами «лемма» и номер, стоит пунктом того же вопроса и раньше этого пункта. Следствие, которое книга ставит сразу после теоремы вопроса как часть той же темы, входит в этот вопрос. Определение следующего вопроса в текст предыдущего положения не вставляется: у него собственная запись и собственный пункт.

Поля `note` и `streams` у вопроса пишутся только в тех вопросах, где они указаны ниже. У пункта `streams` пишется только в случаях из раздела «Потоки у пунктов».

```json
{
  "number": 12,
  "title": "Теорема Больцано–Вейерштрасса.",
  "items": [
    { "statementId": "thm-9-3", "label": "Теорема 3. Больцано — Вейерштрасс" }
  ]
}
```

| Поле | Тип | Правило |
|---|---|---|
| `number` | целое | Номер из таблицы, от 1 до 23. |
| `title` | строка | Дословно из таблицы, включая точку в конце. |
| `note` | строка | Только у вопроса 21, дословно. У остальных вопросов поля нет, если для этой книги не нужна отдельная оговорка. Оговорка не пересказывает чужой учебник. |
| `streams` | объект | Только у вопросов, где он указан ниже. Либо `only`, либо `except`, не оба сразу. |
| `items` | массив | Пункты ответа. Элемент: `statementId`, `label` и необязательный `streams`. |

### Потоки

Имена пишутся точно, иначе ограничение ни к кому не применится:

- `Н.А. Гусев`
- `Я.М. Дымарский`
- `Л.Н. Знаменская`
- `Г.Е. Иванов`
- `В.В. Редкозубов`
- `Е.Ю. Редкозубова`
- `А.А. Скубачевский`

`only` — видно только перечисленным. `except` — скрыто у перечисленных. Нет `streams` — видно всем. Оба ключа в одном объекте запрещены. Пустой массив запрещён: нет ограничения — нет поля.

У пунктов ограничение ставится в двух случаях.

1. Все пункты вопроса 15, если эта глава в книге есть, получают `only` со значением `["Г.Е. Иванов", "В.В. Редкозубов"]`. Если главы в книге нет, `items` равен `[]` и пометок у пунктов нет.
2. Пункт вопроса 19, который отвечает за эквивалентные условия непрерывности, получает `only` со значением `["Н.А. Гусев", "В.В. Редкозубов", "Е.Ю. Редкозубова"]`. Остальные пункты вопроса 19 без `streams`.

Другие пометки у пунктов не ставятся.

### Что входит в ответ на вопрос

В пункты вопроса входят положения этой книги, без которых ответ неполон:

- определения, которыми пользуется формулировка;
- теорема, лемма или следствие, названные в вопросе;
- лемма, которую доказательство пункта называет по номеру;
- следствие, напечатанное в книге сразу после теоремы этого вопроса как вывод из неё;
- замечание, без которого формулировка или критерий не совпадают с книгой;
- пример, который книга приводит как контрпример к условию теоремы этого вопроса.

Не входят: задачи, вводные абзацы, примеры «для иллюстрации», теоремы со звёздочкой и главы, которых нет в вопросе. Не входит определение, которое открывает следующий вопрос: оно остаётся пунктом следующего вопроса, даже если предыдущая теорема заканчивается фразой «напомним, что…».

## Фото страниц

Файл: `public/sources/<id>/pNNN.jpg`. `NNN` — `bookPage` из трёх цифр с ведущими нулями. Страница 6 — `p006.jpg`, страница 40 — `p040.jpg`. Формат JPEG.

`bookPage` — номер, по которому назван файл. Если в PDF печатный номер 12 стоит на кадре 18, в данных `18`, файл `p018.jpg`. Соответствие печатного номера и номера файла описывается в `report.md`.

Если фотографий ещё нет, `pagesDir` всё равно заполнен, а `report.md` перечисляет номера из `bookPages`, для которых файла нет.

9. Повторяющиеся `id`. Таких быть не должно.

## Приёмка

Пакет принимается, когда выполнено всё ниже.

1. Семь JSON-файлов читаются как UTF-8 и проходят разбор JSON.
2. `manifest.id` совпадает с именем каталога и не равен `f1-lectures` или `gusev-2026`.
3. У каждого положения есть все десять полей, лишних полей нет, `kind` из таблицы, `dependsOn` равен `[]`.
4. `id` уникальны. `number` — строка или `null`, не число.
5. Массив положений идёт в порядке книги. Пример стоит сразу после своего положения и в том же `sectionId`.
6. Каждый код в `depends.json`, в `mentions` и в `items[].statementId` есть в `statements.json`. Ссылок на себя нет. В массивах нет повторов.
7. У каждого ключа `formulations.json`, `latex.json` и `short-names.json` есть положение. У каждого пункта вопроса есть формулировка длиннее 8 символов, запись в `latex.json` и короткое имя.
8. Если в книге есть доказательство, и в `text`, и в `latex` оно начинается абзацем `Доказательство.`.
9. `questions.json` содержит 23 вопроса с номерами, названиями, потоками и сноской вопроса 21 из таблицы. Лемма, названная в доказательстве пункта, входит в тот же вопрос.
10. `report.md` отвечает на все 14 пунктов. Тексты не скопированы из другого пакета и не дописаны сверх книги.

## Чего не делать

- Не менять уже сданные пакеты и не менять программу.
- Не переносить формулировки, доказательства и коды положений из другого учебника.
- Не добавлять теорему, определения или задачу, которых нет в этой книге.
- Не класть в JSON отметки «выучено», статистику ответов и выбранный поток.
- Не нумеровать положения номером вопроса коллоквиума, если в книге номер другой.
