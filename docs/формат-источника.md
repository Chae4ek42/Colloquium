# Пакет источника положений

Этот файл — задание агенту, который готовит учебник другого автора для приложения коллоквиума. Приложение уже умеет переключать источники. Агент сдаёт данные одного учебника и не меняет интерфейс, прогресс и чужие пакеты.

Готовый пакет — это набор JSON-файлов. Приложение собирает из них один объект `MathSource` и показывает только его, пока пользователь не выберет другой учебник.

## Что сдать

Каталог `sources/<id>/`:

| Файл | Содержимое |
|---|---|
| `manifest.json` | Код, название, автор, каталог фото |
| `statements.json` | Массив положений в порядке учебника |
| `depends.json` | Рёбра «следует из» |
| `formulations.json` | Короткие формулировки для билета |
| `latex.json` | Тексты с формулами |
| `short-names.json` | Короткие имена карточек |
| `questions.json` | Те же 23 вопроса коллоквиума, что на главной текущего источника |
| `report.md` | Отчёт о покрытии и проверках |

Фото страниц, если они есть: `public/sources/<id>/pNNN.jpg`. В `pagesDir` тогда пишется `/sources/<id>`.

Код `<id>` — латиница в нижнем регистре, цифры и дефис. Пример: `zorich-1`. Код `f1-lectures` уже занят текущим пособием. Новый автор получает новый код. После сдачи код не меняется: прогресс пользователя хранится как `colloquium-progress-v1:<id>`.

В пакет не входят отметки «выучено», статистика тренировки и выбранный поток. Это состояние браузера, у каждого учебника оно своё.

## Критерии приёмки

Пакет принимается, когда выполнено всё ниже.

1. `manifest.json`, `statements.json`, `depends.json`, `formulations.json`, `latex.json`, `short-names.json`, `questions.json` — валидный JSON в кодировке UTF-8.
2. `statements.json` — непустой массив. Каждое положение содержит все поля из раздела «Положение». Лишних полей нет.
3. `id` положений уникальны внутри пакета. Повтор кода недопустим: приложение оставляет только последнюю запись с таким кодом.
4. `kind` — ровно одно значение из списка видов.
5. `number` — строка или `null`. Число JSON недопустимо: `2.10` нельзя превратить в `2.1`.
6. Положения идут в порядке чтения учебника. Этот порядок определяет, к какому положению крепится пример и куда ведёт безымянная отсылка «по теореме».
7. Каждый код в `depends.json`, в `mentions` и в `questions.json` → `items[].statementId` есть в `statements.json`. Чужих кодов нет. Ссылок положения на самого себя нет.
8. У каждой записи в `formulations.json`, `latex.json` и `short-names.json` есть положение с тем же кодом. Пустая строка после обрезки пробелов считается отсутствием текста.
9. Если у положения есть доказательство, в `latex` оно начинается с отдельного абзаца `Доказательство.` — слово и точка сразу после него.
10. Названия вопросов не содержат скобок «для какого потока». Ограничение потока лежит в `streams`.
11. Текст взят из учебника этого автора. Формулировки текущего пособия `f1-lectures` не копируются. Теоремы, доказательства и вопросы, которых нет в переданном источнике, не дописываются.
12. `questions.json` содержит те же 23 вопроса, что главная текущего источника: те же номера, названия, сноски и пометки потоков. Меняется только `statementId` у пунктов — он указывает на положение этого учебника. Пустой список вопросов недопустим.
13. `report.md` содержит проверки из раздела «Отчёт».

## manifest.json

```json
{
  "id": "zorich-1",
  "title": "Математический анализ, том I",
  "author": "В. А. Зорич",
  "pagesDir": "/sources/zorich-1"
}
```

| Поле | Правило |
|---|---|
| `id` | Совпадает с именем каталога. |
| `title` | Название в списке учебников. Без имени автора: автор пишется отдельно. |
| `author` | Как показывать автора. В списке будет строка `автор: название`. |
| `pagesDir` | URL-каталог фото без слэша на конце. Страница 6 открывает `${pagesDir}/p006.jpg`. Номер дополняется нулями до трёх цифр. |

`bookPage` — это номер в имени файла, а не «печатный номер плюс сдвиг». Если в PDF страница с печатным номером 12 лежит на индексе 18, в данных стоит `18`, а файл называется `p018.jpg`. Сдвиг описывается в отчёте. Приложение само сдвиг не прибавляет.

Фото: JPEG, имя `p` + три цифры + `.jpg`. Если фото ещё нет, `pagesDir` всё равно заполняется, а в отчёте перечисляются страницы без файлов.

## Положение

`statements.json` — массив объектов:

```json
{
  "id": "thm-2.9",
  "kind": "theorem",
  "number": "2.9",
  "title": "Больцано — Вейерштрасс",
  "sectionId": "2.5",
  "sectionTitle": "Подпоследовательности",
  "bookPage": 40,
  "bookPages": [40, 41],
  "text": "Формулировка и доказательство обычным текстом, если нет LaTeX.",
  "mentions": ["thm-2.6"],
  "dependsOn": []
}
```

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | Уникален в пакете. Латиница, цифры, точка и дефис. Код попадает в адрес `/p/<id>`. |
| `kind` | строка | Один из видов ниже. |
| `number` | строка или `null` | Номер в учебнике: `"2.9"`, `"1"`, `"4.3′"`. У вводного текста параграфа — `null`. Это не номер вопроса коллоквиума. |
| `title` | строка | Короткий заголовок. На карточке он виден только если нет записи в `short-names.json`. |
| `sectionId` | строка | Код параграфа, общий у положений одного параграфа. Пример ищется внутри того же `sectionId`. |
| `sectionTitle` | строка | Название параграфа. |
| `bookPage` | число | Основная страница, целое ≥ 0. Имя фото строится из этого числа. |
| `bookPages` | массив чисел | Все страницы кнопки «Фото», по возрастанию. Если массив пуст, приложение берёт `[bookPage]`. `bookPage` входит в `bookPages`. |
| `text` | строка | Полный текст без формульной вёрстки: формулировка и доказательство. Одиночный перенос строки приложение склеивает в пробел, пустая строка разделяет абзацы. |
| `mentions` | массив строк | Коды других положений, на которые есть содержательная отсылка и которые не выводятся одной номерной фразой из текста. |
| `dependsOn` | массив строк | Всегда `[]`. Рабочие рёбра лежат в `depends.json`. Приложение заменяет это поле оттуда. |

Виды, строка пишется точно так:

| `kind` | Что это | Куда попадает |
|---|---|---|
| `definition` | Определение | Каталог, граф, карточка |
| `theorem` | Теорема | Каталог, граф, карточка |
| `lemma` | Лемма | Каталог, граф, карточка |
| `corollary` | Следствие | Каталог, граф, карточка |
| `axiom` | Аксиома | Каталог, граф, карточка |
| `principle` | Принцип | Каталог, граф, карточка |
| `remark` | Замечание | Каталог, граф, карточка |
| `example` | Пример | Только блок «Примеры» у положения-хозяина. В каталог и граф не входит |
| `exercise` | Задача | Хранится в пакете, в каталог и граф не входит |
| `prose` | Вводный текст параграфа без собственного номера | Хранится в пакете, в каталог и граф не входит |

Рекомендуемый код: префикс вида, дефис, номер. Префиксы: `def`, `thm`, `lem`, `cor`, `ax`, `prin`, `rem`, `ex`, `task`, `prose`. Пример: `def-1.1-3`, `lem-3.1p`, `prose-1-1`. Префикс приложению не нужен для логики, но код должен быть стабильным и уникальным.

Один и тот же код в двух учебниках допустим. `thm-1.5` Зорича и `thm-1.5` текущего пособия — разные записи. Отметка «выучено» между ними не переносится.

### Примеры

Пример (`kind: "example"`) стоит в массиве сразу после положения, которое он иллюстрирует, и имеет тот же `sectionId`. Хозяин — предыдущее в массиве определение, аксиома, принцип, теорема, лемма, следствие или замечание того же параграфа. Если предыдущего нет, берётся следующее такого вида в том же параграфе.

## depends.json

Объект «код положения → коды положений, из которых оно непосредственно следует».

```json
{
  "thm-1.5": ["ax-1-2", "def-1-6"]
}
```

Ребро означает «в доказательстве используется это положение», а не «в тексте встретилось похожее слово». В список попадают только прямые опоры. Кода, которого нет в `statements.json`, быть не может. Положение не ссылается само на себя.

Ключ без рёбер можно не писать. Отсутствующий ключ и `"thm-1.5": []` для приложения одно и то же.

Номерные фразы в тексте («по теореме 2.9») в этот файл не дублируются: приложение само находит их в `latex` или в формулировке. В `depends.json` остаётся то, что из текста фразой не находится. `mentions` — для отсылок, которые не являются ребром «следует из» и не ловятся номерной фразой.

## formulations.json, latex.json, short-names.json

Все три файла — объекты «код положения → строка». Ключ без текста не пишется.

Порядок выбора текста на карточке и на странице положения:

1. `latex.json`, если после обрезки пробелов строка не пустая.
2. Иначе `formulations.json`.
3. Иначе `text` из положения.

`formulations.json` — формулировка, которую произносят на билете. Без доказательства. Одна запись — один абзац или несколько абзацев, как в книге.

`latex.json` — тот же текст с формулами KaTeX. Формулировка и доказательство вместе. Доказательство начинается отдельным абзацем:

```text
Формулировка теоремы.

Доказательство.
Текст доказательства.
```

Слово `Доказательство` без точки сразу после него доказательством не считается. Фраза «Доказательство отсутствия…» внутри формулировки доказательством не считается.

Правила KaTeX:

- Строчная формула: `$...$`. Выключная: `$$...$$`.
- `\emph{...}` допустим: приложение превращает его в курсив.
- `\tag` допустим только внутри `$$...$$`.
- Обратный слэш в JSON экранируется: в файле написано `\\frac`, на экране это `\frac`.

`short-names.json` — имя карточки из нескольких слов. Оно не повторяет формулировку. На карточке получается «Теорема 2.9. Больцано — Вейерштрасс». Если записи нет, карточка называется «Теорема 2.9». Для примера без короткого имени карточка называется «Пример».

## questions.json

Вопросы на главной — лист коллоквиума от 01.10.2026. У нового учебника они те же, что у текущего источника: номера 1–23, названия, сноски `note` и пометки `streams` у вопроса и у пунктов. Другой список вопросов не составляется.

Меняется привязка пункта к книге. `statementId` — код положения этого учебника, которое закрывает тот же пункт билета. `label` остаётся таким же, как у текущего источника, если пункт тот же по смыслу. Если в этом учебнике такого положения нет, пункт не выдумывается: он пропускается, а в `report.md` пишется, какого пункта не нашлось. Вопрос при этом остаётся в списке.

Эталон — `src/data/math/questions.ts` текущего источника. Сверяются `number`, `title`, `note` и `streams`. Расхождение в этих полях — ошибка пакета.

```json
{
  "number": 12,
  "title": "Теорема Больцано–Вейерштрасса.",
  "items": [
    { "statementId": "thm-2.9", "label": "Теорема 2.9" }
  ]
}
```

Поля `note` и `streams` пишутся только там, где они есть у того же вопроса в текущем источнике. Пример выше — вопрос 12: сноски и пометки потока у него нет.

| Поле | Правило |
|---|---|
| `number` | Целое, номер вопроса на листе. Номера идут без пропусков, обычно с 1. Прогресс вопроса хранится отдельно как `q<number>`, например `q12`. |
| `title` | Название с листа. Скобки с фамилиями потоков в название не входят. |
| `note` | Необязательная сноска. Нет поля — нет сноски. |
| `streams` | Необязательное ограничение всего вопроса. |
| `items` | Пункты того же вопроса из текущего источника. `statementId` есть в `statements.json` этого учебника. |

`streams` — объект с одним из полей:

- `only`: массив имён. Вопрос или пункт виден только этим потокам.
- `except`: массив имён. Вопрос или пункт скрыт у этих потоков.

Оба поля сразу не заполняются. Нет `streams` — видно всем.

Имена, которые понимает фильтр приложения, пишутся точно:

- `Н.А. Гусев`
- `Я.М. Дымарский`
- `Л.Н. Знаменская`
- `Г.Е. Иванов`
- `В.В. Редкозубов`
- `Е.Ю. Редкозубова`
- `А.А. Скубачевский`

Другое написание фамилии ни с одним потоком не совпадёт. Фильтр «Другой» скрывает всё, у чего есть `only`, и показывает то, у чего есть только `except` или ограничения нет. Фильтр «Все вопросы» показывает всё.

Пометки потоков копируются с текущего источника и не снимаются из-за того, что у нового автора нет своих потоков. Вопрос, у которого для выбранного потока не осталось ни одного пункта, на главной скрывается.

## Как приложение само строит связи

Агенту не нужно сдавать граф отдельно.

Предшественники положения — объединение трёх списков, без повторов:

- коды из `depends.json`;
- номерные ссылки, найденные в `latex`, а если его нет — в формулировке;
- `mentions`, кроме ссылки на себя.

«Из чего следует» — этот список. «Куда ведёт» — обратные рёбра к теоремам, леммам и следствиям. «Где используется» — обратные рёбра к остальным видам.

Номерная ссылка ищется по виду и номеру среди положений этого пакета. Фраза «теорема 2.9» находит положение с `kind: "theorem"` и `number: "2.9"`. То же для леммы, следствия, определения, аксиомы и принципа. Номер сравнивается без пробелов; штрих `′` и `'` считаются одним знаком. Если номер встретился дважды, берётся положение того же `sectionId`, иначе первое в массиве.

Короткая запись `т. 2.9` тоже ищет теорему с номером `2.9`.

Безымянные «по теореме» и «применяем теорему» без номера ведут к предыдущей теореме в массиве положений.

Ссылка положения на самого себя не ставится.

Именные ссылки ниже привязаны к кодам текущего пособия. В новом пакете они оживут только если положение с таким кодом есть. Если теорема в новом учебнике другая, эти фразы ссылкой не делаются: код под них не занимается.

| Фраза в тексте | Код, который ищет приложение |
|---|---|
| Больцано — Вейерштрасс | `thm-2.9` |
| Гейне — Борель | `thm-3.2` |
| де Морган | `thm-1.1` |
| Бернулли | `lem-1.4` |
| Архимед | `thm-1.6` |
| Штольц | `thm-2.8` |
| Вейерштрасс, если перед этим нет «Больцано» | `thm-4.7` |
| Кантор и «вложенных», либо параграф не начинается с `4` | `thm-2.7` |
| Кантор в параграфе на `4`, без «вложенных» | `thm-4.10` |
| критерий Коши про последовательности или в параграфе на `2` | `thm-2.11` |
| критерий Коши в остальных местах | `thm-4.2` |
| определение Коши | `def-4.1` |
| определение Гейне | `def-4.2` |
| следствие теоремы 2.10 | `cor-2.5-1` |
| следствие теоремы 4.3 | `cor-4.4-1` |
| следствие теоремы 4.8 | `cor-4.6-1` |

Для обычных «теорема N», «лемма N» и остальных номерных фраз достаточно совпадения `kind` и `number`. Отдельный код из таблицы не нужен.

## Отчёт

`report.md` отвечает на каждый пункт:

- учебник, автор, код источника;
- сверка вопросов с главной текущего источника: номера, названия, сноски и потоки совпали; какие пункты не нашлись в этом учебнике;
- число положений всего и по каждому `kind`;
- первая и последняя `bookPage`;
- сколько положений имеют LaTeX, сколько только формулировку, сколько только `text`;
- список кодов без текста во всех трёх слоях — таких быть не должно;
- список повторяющихся `id` — таких быть не должно;
- список кодов из `depends`, `mentions` и вопросов, которых нет среди положений — таких быть не должно;
- список вопросов с пустым `items` — таких быть не должно;
- страницы из `bookPages`, для которых нет `pNNN.jpg`;
- соответствие печатного номера и индекса PDF, если они различаются;
- что сознательно не включено, потому что этого не было в источнике.

## Чего агент не делает

- Не меняет текущий пакет `f1-lectures`.
- Не переносит в новый пакет формулировки, доказательства и вопросы из текущего пособия.
- Не дописывает теоремы, которых нет в учебнике этого автора.
- Не кладёт в данные «выучено», статистику и выбранный поток.
- Не меняет логику приложения. Подключение пакета — отдельный шаг: объект `MathSource` добавляется в список в `src/data/math/bank.ts`. Поля объекта те же, что в файлах пакета: `statements`, `depends`, `formulations`, `latex`, `shortNames`, `questions`, `pagesDir`, плюс `id`, `title`, `author`.
